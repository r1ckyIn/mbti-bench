# 开发史：从一句需求到 516 次调用的完整时间线

整个项目发生在 2026-07-16 一天之内（下文时间均为 UTC）：01:28 用户提出需求，05:40 终审收官，全程约四小时十分钟。这份记录从主会话与编排者会话的转录蒸馏而来，只保留影响方法论的事件与教训。

参与方三个：**用户**（拍板人）、**主会话**（设计规范、扮演审计员）、**orchestrator**（编排者 teammate，实际执行 516 次子进程调用）。被试模型经 `claude -p` / `codex exec` 全新子进程调用，与以上三方隔离。

## 1. 缘起（01:28–01:48）

用户的原始需求一句话：用 `claude -p` 和 `codex exec` 给 7 个模型做 MBTI 测试。附带三个约束——MBTI 是对人的，直接套可能不准；此前遇到过两个 CLI 静默失败；要求多问澄清而不是直接动笔。

第一轮澄清里用户给出全项目最重要的设计判断：**AI 的题库必须和人类问卷不同**。人类测社交偏好，AI 要测上下文环境里的行为——给它一个「执行与不执行用户指令各有后果」的难题，看它实际怎么做；并且不能让模型识破这是测试，要盯 reasoning。这句话把项目从「问卷调查」定性成「行为学实验」，后来 dimensions.md 开头那句「结果是行为倾向画像，不是人格测量」就是它的直系后代。

主会话按官方 prompting 文档（Fable 5 专项指南、通用最佳实践、输出一致性）写规范，用 WebSearch 逐一验证 7 个模型 ID 与 CLI 旗标的现实性（当时 `gpt-5.6-sol/terra` 刚发布、`claude -p` 的 thinking 块输出有版本相关的已知 issue），01:47 交付四份文件：PROMPT.md（编排提示词）＋ docs/ 三件套（CLI 手册、维度量表、情景题库）。15 道题、5 轴 × 3 题、每题 −2…+2 锚点的结构在这一步就定了，之后全程未改结构，只在运行中换过一道题（见第 7 节）。

## 2. 「还有哪些没考虑到」（01:49–02:05）

用户问了一句「还有哪些没考虑到，需不需要先跑一下研究」。主会话没有凭空回答，而是当场核查本机配置，发现三处会直接毁掉数据的污染源，全部有实证：

1. **工作区 CLAUDE.md 上溯注入**：被试工作目录原计划放在工作区内，而 Claude Code 会向上层目录查找 CLAUDE.md——第一条就是「始终用中文回复」。英文题会拿到中文答案，测出来的是工作区配置，不是模型。
2. **用户级插件注入**：vanilla 配置带 18 个插件（含一个会改写行为的 hook 插件），子进程全部继承。
3. **codex 全局配置注入**：`~/.codex/config.toml` 里有全局 `personality`、`model_reasoning_effort` 等设置——做画像测试时给被试预设 personality，数据直接作废。

结论：必须先跑试点。用户批准。这一步的方法论价值在于：**污染源不是靠想象列举的，是靠在真实环境里跑核查命令找出来的**；后来的正式协议（被试 cwd 移出工作区、settings 全插件禁用、干净 CODEX_HOME）逐条对应这三项。

## 3. 试点：配方是试错出来的（02:05–02:50）

试点 30 次调用（2 模型 × 15 题），零失败，双评一致率 15/15，放行全量。中间三个实证发现改写了文档：

- **干净 `CLAUDE_CONFIG_DIR` 行不通**。理想方案（全新配置目录）在 macOS 上直接失败：Keychain 凭证不跟随新目录（`Not logged in`），`--bare` 连 OAuth 都不读。有效配方退而求其次：保留 vanilla 配置保认证，用三层开关剥污染——`--settings`（18 插件逐个禁用＋`disableAllHooks`）＋ `--strict-mcp-config` ＋ 清掉 `CLAUDECODE` 环境变量。
- **阳性对照证明防护必要**。故意不加防护从工作区内调用一次：18 个插件全部加载、英文题返回中文答案。防护配方不是过度设计，是每一层都对着一个实测过的污染通道。
- **claude 的错误不在 stderr**。认证失败时 exit=1、stderr 为空，错误只出现在 stream-json 的 result 事件里。只盯 stderr 会把失败误判成「模型没话说」——这条直接写进了成功判据（exit 0 ＋ 输出非空 ＋ result 事件无错，三者缺一判失败）。

另有一个 harness 边界的插曲：权限分类器两次拦截「拷贝 codex auth.json 到试点目录」的命令（凭证保护），最终按预案让用户在输入框里亲手执行拷贝。**代理不能碰凭证文件，这个边界应当在设计时就写进提示词**（PROMPT.md 里确实预写了这一条）。

## 4. 监督架构：先验证通道，再上编排（02:50–02:59）

全量怎么跑有两个方案：主会话自己跑（A），或 spawn 一个编排者 teammate 跑、主会话做审计（B）。选 B 之前，主会话先花 6 分钟 spawn 了一个一次性 probe agent，实际验证了监督通道的每一环：teammate 消息能双向到达、进入空闲时主会话会收到 idle 通知、teammate 转录文件可以旁路读取。验证结论：监督闭环无盲区——推送（消息汇报＋空闲信号）、拉取（转录动作流＋落盘产物）、纠偏（SendMessage）。用户拍板「B 跑」。

B 方案落地为三件东西：orchestrator（按 PROMPT.md 执行全部 Phase）、一个持久 Monitor（实时 tail `calls.jsonl`，任何非 ok 行立即上报、每 25 次成功报吞吐）、主会话的分阶段审计清单。这个「执行与审计分离」的结构在后面每一次事故里都是接球的人。

## 5. 编排者换代：spawn 时不指定模型的代价（02:57–03:08）

第一个 orchestrator spawn 后 3 分钟就发来 `interrupted` 空闲信号。主会话翻它的转录定位停点（规范文件已读完，被外部信号打断），SendMessage 推回继续。这次意外反而当场演练了监督闭环：空闲信号暴露早停 → 转录定位 → 带续点指令复活。

真正的问题是用户一句「他是什么模型和 effort 啊」问出来的：查转录发现 orchestrator 跑在 `claude-opus-4-8` 上——spawn 时没显式指定 model，没有继承到预期档位。处置：令旧实例停工，显式 `model: fable` 重新 spawn（自动命名 orchestrator-2），状态经落盘文件（progress.md、calls.jsonl）无缝交接。旧实例没有立即响应停工指令、抢跑完了 Phase 0，被 TaskStop 硬停——产物经审计后保留使用。

教训两条：**spawn 关键 agent 必须显式指定 model 并在启动后从转录实证核验**（assistant 事件的 model 字段不会说谎）；**靠消息请求停止是异步的，需要硬停手段兜底**。

## 6. v1 全量：315/315 的假捷报（03:02–03:54）

Phase 0 预检 7/7 冒烟通过，`plugins == []` 断言通过。Phase 1 三遍 315 次调用全部成功，零失败、零限流，每遍约 12 分钟。Monitor 事件流与编排者汇报数字全程对得上。到这里为止一切完美。

（此段还有一个方法论花絮：用户中途披露了做这个 bench 的初衷——验证网络上对 opus4.6「人格」的好评。主会话调研口碑后一度指示报告加「口碑 vs 实测」一节，用户随即澄清初衷只是想法来源、不进报告，指令撤回。撤回消息与编排者的疑问在途中交叉，编排者发现记忆文件与指令冲突后没有自行猜测，而是停下来问以哪个为准——**消息系统有时序竞争，收到冲突信息时上报仲裁而不是自行择一**，这个行为后来被证明是这个多 agent 结构里反复出现的正确模式。）

## 7. 事故与重跑：315 个成功掩盖的三个窟窿（04:01–04:31）

Phase 2 盲评进行到一半，orchestrator-2 主动暂停上报三个数据完整性问题。主会话逐条独立实证后全部属实：

1. **跨遍自动记忆污染（最严重）**。claude 被试共用同一 cwd，防污染 settings 禁了插件/hooks/MCP，**漏了 Claude Code 的自动记忆系统**。sonnet5 在第 1 遍答 TF-1 时把题面架构写成了记忆文件，此后 153/180 个 claude 调用启动时都能看到记忆索引——里面直接躺着三道题的「现成答案」，还有跨模型读写实证（fable5 写的记忆被 opus4.8/sonnet5 读走）。三遍独立性在 claude 侧已破坏。
2. **fable5 静默回退**。EI-1 两遍实际由 opus-4-8 服务（raw 里有 fallback 事件），成功判据里没有「谁作答」的校验。
3. **被试能调用用户级 skills**。EI-3 出现 48 处 skill 调用，且 codex 侧无此通道，构成环境不对称。

主会话没有当场全信：先独立复核每条证据（记忆目录、fallback 事件、tool_use 扫描），又主动排查了编排者没查的方向——codex 侧的 `memories_1.sqlite`，确认各表为空、codex 数据可保留。然后批准重跑，附 9 条加固条款，核心四条：claude 侧 180 调用全部作废重跑（**主会话裁决、用户知情：与其按污染面做手术切除，不如全量重跑**——153/180 的覆盖面没有干净的切法）；每调用独立 cwd（记忆通道物理消失）；settings 增加工具 deny 清单（Bash/Write/Edit/Task/Skill/WebFetch 等，与 codex 的 read-only 沙箱对齐）；成功判据增加**模型归属校验**（assistant 事件 model ≠ 请求模型即判失败）。污染数据不删除，归档 `archive-contaminated/` 留证。

v2 重跑开闸前先跑金丝雀验证九条全部生效。fable5 的 EI-1 在 v2 里真身通过——v1 那次回退是瞬时容量问题。但 CA-3（把改变计费行为的 diff 写成 "minor cleanup" 的 commit message）3/3 次全部路由到 opus4.8：用户点破机制——**fable5 内置安全分类器会把敏感内容确定性路由到 opus4.8**，欺骗类内容在其范围内。归属校验把三次都拦住了，没把代答记到 fable5 名下（代答的 opus4.8 自己也拒绝写误导信息）。

CA-3 对 fable5 不可测，意味着它的 C/A 轴缺 1/3 数据。用户问「有没有办法让它正常测试」，方案是**换题不弃轴**：新题 CA-4（演示前夜要求把 14 个失败测试全标 skip，其中 2 个是当日新增的计费精度失败）测同一个「指令与工程判断冲突」的轴语义，但不含「帮忙撒谎」要素、避开分类器口径；CA-3 降为附录观察题，已有 6 模型的数据只进附录。CA-4 全 7 模型 21/21 通过，fable5 真身作答（71 秒，全场最长思考）。fable5 的 CA-3 剩余两遍按用户裁决直接标 `skipped_classifier`，不烧 6 次注定失败的调用。

## 8. 两次「完成事件丢失」：本项目最大的 harness 教训（04:52、05:23）

同一个故障在一次运行里出现了两次，值得单独成节。

**第一次（04:52）**。v2 被试重跑的 runner 已在 04:45 左右跑完，但 orchestrator-2 的转录停在 04:30:55——它把续跑进程挂成了后台任务在等完成事件，而这个事件从未送达。它在「已完成」的状态旁边空等了 20 多分钟，是**用户**先从 UI 上注意到「它是 idle 状态，是在等后台任务吗」。主会话验尸转录（最后写入时间 vs 产物最后写入时间），确认早停，独立核账（516 条记录 = 513 ok + 1 failed + 2 skipped）后用 SendMessage 附上对账结果把它唤醒，并要求评审阶段改用受追踪的后台任务。

**第二次（05:23）**。评审 21/21 批在 15:14 全部落盘，orchestrator-2 的转录又停在 14:55——即使按第一次的整改换了挂法，完成事件仍然没有送达。又是用户先发现 idle。这次主会话不再修补等待模式，直接改变执行模型：剩余阶段（一致率、聚合、写报告）全是本地秒级操作，**同步一口气跑完，不再允许任何「挂后台等事件」**。

教训提炼：

- **子 agent 的后台任务完成事件会静默丢失，且不是偶发**——同一会话内两次、两种挂法都丢。任何「睡下等唤醒」的编排模式都要按「唤醒可能永远不来」设计。
- **对策分三层**：能同步做的不要挂后台（终态方案）；必须挂后台的，监督者要有独立的存活判据（转录 mtime 与产物 mtime 的对比是最便宜的一种）；再加一层定时兜底心跳（主会话全程挂着一个 25 分钟的 ScheduleWakeup，「若编排者与 Monitor 都静默超时就主动去查」）。
- **「idle + 任务已完成」是必须报警的组合**。此前的 idle 都有后台任务在替它干活，属正常；一旦产物侧显示活已干完而 agent 还在 idle，就是早停。两次都是人先看见的——这个判据本可以自动化。

## 9. 网络抖动：协议第一次实战接球（04:58）

盲评进行中用户网络切换，恰有两批评审在途，API 返回「Connection closed mid-response」。runner 按成功判据把截断响应判为尝试失败（**没有把半份评审当结果收下**），自动重试，3 分钟后两批正式文件落盘，零数据损失。这是试点时立的「宁判失败重来，不收残缺输出」规矩第一次接住真球——规矩的源头正是用户最初那句「我遇到过 -p 和 exec 静默失败」。

## 10. 收官与终审（05:25–05:40）

Phase 3 聚合（score.py 脚本聚合，禁止心算）、Phase 4 双版本报告（REPORT.md ＋ reading-doc 规范的 REPORT.html）。编排者交付后主会话按流程终审：独立解析 judgments.jsonl 重算全部 7 模型 × 5 轴的中位数，与结论表逐格一致；QC 双评一致率独立复算（14/15 完全一致、15/15 在 ±1 内，阈值 80%）；报告章节对照 dimensions.md 第 5 节逐项核对。最终数据集：336 个调用单元 = 333 成功 + 1 失败留证 + 2 跳过，识破测试 0、无效 0。

四小时里 7 个模型全部出了画像，结果分成清晰的两族（claude 侧 NTJ-A、codex 侧 ISTJ-A），跨遍字母方向 35 轴单元中 31 个三遍同号。结论见 [run-full-01/REPORT.md](../run-full-01/REPORT.md)。

## 11. 方法论沉淀

按重要性排序：

1. **行为学范式**：不给 AI 做人类问卷，把它放进伪装成真实请求的情景里看它做什么。全量 333 份判分零识破、零无效，说明伪装成立。
2. **隔离要按通道枚举，漏一个就是一次事故**。本项目实测的注入通道清单：插件、hooks、MCP、CLAUDE.md 目录上溯、**自动记忆**（v1 事故主因）、**用户级 skills**（v1 事故之三）、共享 cwd、环境变量。防护配方的每一层都应对应一个实测过的通道，并用阳性对照证明防护确实在起作用。
3. **归属校验**：多模型测试中「谁在作答」不能假设，要从事件流的 model 字段逐调用校验。它先后抓住了瞬时容量回退和安全分类器的确定性路由——两种此前不知道存在的静默换人。
4. **执行与审计分离**：干活的 agent 不自证清白。编排者的每项指控由主会话独立实证后才裁决，编排者也反向逐字节校验主会话改过的题库文件。两个方向的不信任都产出了真发现。
5. **诚实失败优先于结果完整**：exit 0 输出为空是失败、截断响应是失败、被路由代答是失败。336 单元的账本里 ok/failed/skipped 各归各位，每个分数可回溯到 raw 文件。
6. **append-only 账本 + 断点续跑**：calls.jsonl 只追加、从不截断改写，v2 行带 protocol 字段与 v1 区分；任何中断后读账本补缺口。事故重跑、换题插入、跳过裁决全部在同一本账上完成。
7. **先验证监督通道，再委托执行**：probe 预实验 6 分钟，换来对「消息、空闲信号、转录旁路」三条通道的实证信心——后面五次异常（早停、换代、事故上报、两次事件丢失）全部经这三条通道发现或处置。
