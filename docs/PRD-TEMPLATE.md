# 附录：模板使用指南

## A. 章节必要性判断

| 章节 | 何时需要 |
|------|----------|
| 三、核心概念 | 涉及领域专业术语时 |
| 六、配置文件格式 | 支持配置文件时 |
| 十二、面试准备要点 | 用于求职项目时 |
| 十三、参考资料 | 有外部依赖/学习资源时 |

## B. 优先级定义

| 优先级 | 定义 | MVP 包含 |
|--------|------|----------|
| P0 | 核心功能，没有则项目无价值 | ✅ |
| P1 | 重要功能，显著提升体验 | 视时间 |
| P2 | 锦上添花，可后续迭代 | ❌ |

## C. 用户故事格式

```
作为 [角色]，
我希望 [做什么]，
以便 [达到什么目的]。
```

**好的用户故事**：具体、可验证、有价值
- ✅ 作为 SRE 工程师，我希望按内存使用率降序查看 Pod，以便快速定位内存告警的根源。
- ❌ 作为用户，我希望工具好用，以便提高效率。（太模糊）

## D. 命令设计原则

1. **遵循生态惯例**：复用已有工具的 flag 命名（如 kubectl 的 `-n`, `-l`, `-o`）
2. **短选项用于高频**：常用参数提供短选项（如 `-n` 代替 `--namespace`）
3. **合理默认值**：80% 场景不需要额外参数
4. **组合使用**：flag 之间独立，可任意组合

## E. 输出格式原则

| 格式 | 用途 | 设计要点 |
|------|------|----------|
| Table | 人类阅读 | 列对齐、颜色区分、汇总行 |
| JSON | 程序处理 | 结构稳定、null 处理明确、可被 jq 解析 |
| YAML | K8s 生态 | 符合 K8s 资源格式习惯 |
